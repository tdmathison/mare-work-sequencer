# Tools navigation

The top-level Tools item reuses Settings' centered-chevron dropdown component,
hover/keyboard/touch behavior, viewport positioning, 14px icon, and compact 52px
minimum desktop bar. API is immediately before Tools; unrelated item order, API
permissions and API destination are unchanged. Only one dropdown is shown at a
time. Escape closes an open hovered or keyboard-opened menu without interfering
with an active native unsaved-changes dialog.

The shared `analyst_tools` registry supplies both the page tabs and dropdown entries.
Current registry order is CyberChef, Text Manipulation, Snort Rule Builder, YARA
Rule Editor. Labels use each registered tool's name. Enabled/permission filtering
is shared by both lists, while existing backend `require_tool` checks still protect
all tools and their assets/actions. Missing CyberChef assets retain the existing
setup/error behavior; navigation does not change installation availability policy.

Tools' text link points to the first authorized tool. No dropdown is rendered if
none are available. `/tools` remains a supported first-available workspace bookmark;
`/tools/<tool_id>` remains the direct, server-validated tab URL. Unknown or disabled
tools return 404; unauthorized tools return 403. Native tool iframe `/app/`, state,
draft and action routes are unchanged.

Page-tab selection and same-window dropdown links update browser history and the
current dropdown indication. The existing tabs remain visible. Back/Forward changes
the selected tool through the same controller; cancelling its leave guard restores
the previous history entry. Refresh preserves selection using the URL. Modified
clicks, middle clicks and new-tab links retain normal anchor behavior. URL paths
are generated by Flask, including script prefixes.

Switches keep existing lazy-loaded iframe panels alive, retaining in-memory editor
buffers and undo state. Before leaving a tool, the controller calls its existing
`mareCanLeaveTool` hook. In particular, YARA's existing Save / Discard / Cancel dialog
and account-draft persistence are reused. Save must finish successfully before the
new tab is selected; Cancel retains the current buffer and selection. Guard failure
also prevents navigation. New history state contains only tool identity and position,
never editor text or credentials. Browser refresh and leaving the workspace retain
each tool's existing draft/reload behavior; no new storage model is introduced.

## Verification

```
.venv/bin/python -m pytest -q tests/test_tools.py tests/test_navigation.py tests/test_settings_navigation.py tests/test_text_manipulation.py tests/test_yara.py tests/test_snort.py
node tests/browser/tools-navigation.cjs
node tests/browser/settings-navigation.cjs
```

Server checks cover registry order and uniqueness, first-authorized selection,
permission/availability filtering, direct URLs, backend protection and active
navigation. Browser checks use isolated data and Chrome to exercise every registry
entry, API ordering, desktop geometry and overlay stability, continuous hover,
keyboard/Escape/outside dismissal, touch and narrow viewport bounds, direct/new-tab
links, refresh/history, retained editor identity/buffers, and actual YARA Cancel,
Discard and Save-before-navigation with restored file bytes. Settings' complete
browser regression suite remains applicable. Real Snort integration requires its
existing optional executable/profile/isolated runner configuration; navigation tests
do not establish engine compatibility. Firefox/Safari remain unverified.
