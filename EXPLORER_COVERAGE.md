# Investigation Coverage & Knowledge Gaps

The authenticated Explorer's bottom dock is a read-only inventory of saved content. Its collapsed/open state is local browser preference, separate from Saved Views. Opening, closing or changing tabs does not rearrange nodes or reset zoom, pan, selection, expanded categories, focus, paths or shared-indicator settings. A smaller graph can require panning to objects previously below its new boundary; Fit View remains an explicit user action.

## Coverage definitions

- **Indicators:** nonblank saved Type/Value rows accepted without errors by `indicator_types.analyze`, including each row's saved detection intent, across all saved indicator sections. Blank values and invalid rows do not count. Legacy `indicator_tables` is used only when no section record exists, matching `load_table`. Repeated valid saved entries count as entries, not unique observables. Exportable contextual types and filenames count here; this is deliberately different from Shared Indicators matching.
- **ATT&CK and MBC:** independently inspect canonical `mappings/mitre-attack.md` and `mappings/mitre-mbc.md`. These are free-form editors, not authoritative structured mapping tables, so the dock reports saved content presence without inventing mapping counts. Heading-only content, empty default table headers/separators, comments and recognized placeholder prompts do not count.
- **Report:** meaningful saved Markdown in the four editable analyst sections in `reporting.SECTIONS`. Key Findings falls back to legacy `threat_overview.md` only when the canonical file does not exist, matching the report reader. Generated mapping/indicator/appendix sections, rendered Word/PDF files, default headings, exact scaffold prompts, comments, TODO/TBD and blank editors do not establish analyst report coverage. This is a conservative content check, not an authorship classifier; arbitrary pasted boilerplate cannot reliably be identified without provenance that the application does not store.
- **Package Content:** `planned_standard` supplies exactly the Standard export's planned files, including its current saved-indicator STIX projection and existing exclusions for samples, symlinks, backups, report Markdown/source assets and the current working Word report. Qualifying content is a nonempty included file, CSV with nonblank data rows, Markdown beyond empty scaffolding, or generated STIX with non-grouping objects. Empty STIX bundles and archive-generated README/manifest wrappers do not count. The displayed count is qualifying included content files, not deliverables completed. A stale CSV still included by the exporter may therefore produce package presence independently of current Indicators coverage. No archive is generated or downloaded by this feature.

An explicit saved `readiness.status = 'Not applicable'` for `iocs` applies to an otherwise missing Indicators cell. The corresponding explicit `mappings` decision applies to otherwise missing ATT&CK/MBC cells. Actual content takes precedence. Other readiness states do not determine coverage. There is no aggregate applicability decision for Package Content and no new applicability workflow; the existing application requires a report. Restricted or unreadable content remains **Unavailable**, never Not applicable.

Missing-content sorting counts four categories: Indicators, ATT&CK/MBC, Report and Package Content. The combined catalog category counts once if either catalog is missing; it is excluded if either is unavailable. Unavailable and explicitly not-applicable categories do not add to the missing count. Coverage does not assess quality, readiness or lifecycle completion.

## Scope, authorization and gaps

Current Graph is the current visible entity set after filters and focus depth, excluding temporary outside-filter path objects. Canvas pan/zoom does not change this set. All Accessible Cases uses the same global `cases:read` eligibility as the board. Deleted cases disappear. Existing granular indicator/report/asset/reference read permissions gate each category; the aggregate package cell requires all four content permissions. Restricted cells disclose no counts or content links.

Suggestions require `tags:read`. Missing-profile tags are deduplicated across scoped accessible cases and use the existing `/malware-families/new?tag_id=...` or `/threat-actors/new?tag_id=...` identity-checked creation flow. Create actions require `tags:manage`, matching those pages. Profiles without references have neither an OSINT record nor an attached report record. Current Graph considers profiles represented in that graph; All Accessible Cases considers profiles linked directly through its case tags. Associations alone do not establish a gap. Supporting case counts include only scoped authorized cases, with at most five example links. Profile review remains a read-only navigation action for readers.

## Runtime and refresh

One batched endpoint returns 50 coverage rows and 50 gap suggestions per page. Filtering and missing-category sorting happen over the inspected scope before pagination. Indicator/section and readiness queries are batched; there is no per-cell request or per-case indicator SQL lookup during package planning. OSINT/report existence is queried with indexed backing relationships. Filesystem reads use the existing saved package hierarchy and safe Standard selection rules, without scaffolding or writes.

Inspection is bounded to 2,000 cases and five seconds checked between cases. When limited, the dock explicitly reports the inspected/full case count, and filtering, sorting and case-derived gaps apply to that subset. One particularly large case can exceed the inter-case time target. Indicator carriers over 16 MiB, a cumulative 64 MiB carrier payload, invalid section data, over 10,000 rows per case or text files over 1 MiB produce Unavailable cells rather than misleading missing statuses. A wide scope can therefore be partial; narrow Current Graph for detailed inspection. Disk content is not a transactional filesystem snapshot; concurrent saves can require a refresh. No derived findings or cached content are persisted and no database migration is needed.

Scope/filter changes cancel stale client requests; generation checks prevent stale responses from replacing newer results. Opening the dock, graph refresh/scope changes, returning to the browser tab/window and the manual Refresh action reload current stored data. There are no in-canvas content editors to hook. Returning from a case/profile editor refreshes on page show/focus; external changes become visible on the next refresh.
