# SDK implementation report

The package supports Python 3.10+, httpx pools, pydantic request/response models, explicit resource namespaces, synchronous and asynchronous clients, environment/constructor bearer credentials, standard logging, typed sanitized errors, safe-read retries, Retry-After, bounded connection settings, multipart uploads and atomic streamed downloads. `mws_sdk` contains no backend/database imports. Both repository-root and standalone `sdk/` editable installs are supported.

The versioned API retains the existing cases/tasks/notes/indicators/references/reports/templates/packages/roles/users/settings/metrics/token/sync operations. `api_extensions.py` publishes reviewed adapters for coverage, Explorer/saved views, profiles and relationships, tags, search, audit exports, tools and durable encrypted backup jobs. Shared handlers retain existing validation/authorization/audit logic; profile JSON edits preserve omitted data, and content edits reuse the API's existing open-case guard. The original final-report handler needed a correction: its unconditional cleanup rollback erased the pending report-path update when CaseSync deferred commit. Cleanup now rolls back failures only; existing upload/download tests cover the correction.

No new authentication mechanism, role model, database fields or plugin architecture is introduced. Existing hashed bearer tokens are reused. Generated request IDs and token-ID mutation audit metadata improve traceability without logging credentials, bodies or file contents. Full backups use existing passphrase-protected jobs; the deprecated raw database endpoint remains HTTP 410 and deliberately has no nonfunctional SDK method.

[API coverage](API_COVERAGE.md) lists every versioned operation and SDK mapping. [Discovery](DISCOVERY.md) explains browser-only, operator-only, engine-dependent and retired capabilities. [README](../README.md) contains installation, sync/async examples, workflow and integration instructions. [API reference](API_REFERENCE.md) is generated from shipped method/model docstrings. `examples/` scripts use environment credentials and require explicit flags for writes.

Validation commands and their measured results are recorded in the implementation's final response. The unit suite mocks HTTP for every resource operation in both clients, plus pagination/auth/errors/retries/files/cleanup. Integration tests use the repository's disposable backend conftest and in-process WSGI transport; they have no live target URL setting. Core existing API/documentation/report/backup/Explorer tests remain part of regression verification. Standalone wheels are checked for server/database dependency exclusion.

## Measured verification

- 152 public SDK resource operations, with identical sync/async signatures, generated from 153 versioned API operations; the sole unmatched operation is the explicitly retired HTTP-410 database backup. 284 typed models are shipped.
- 541 focused tests pass across SDK unit tests and relevant API/documentation/report/backup/Explorer/profile/tag/indicator regressions. Of these, 335 are standalone SDK mocked tests, including every operation in both transports.
- Exact repository-root `pip install -e .` succeeds. Both root and standalone SDK wheels build; an isolated wheel install runs a mocked client without importing Flask or sqlite3. Shipped code parses with Python 3.10 grammar; the runtime test environment is Python 3.11. Other supported Python versions were not separately executed.
- Broad backend check (excluding the uncollectable sample test): 584 passed, 4 skipped, 10 failed. All ten failures reproduce against a read-only archive of the unchanged branch HEAD. They concern existing audit/navigation/autosave/workflow/import expectations. `tests/test_samples.py:21` has a pre-existing indentation error that blocks full collection. These unrelated baseline failures are not represented as SDK successes and were left unchanged.
- The API documentation browser suite passes with installed Chrome: GET/write/upload/download/errors, session gating, offline loading, WSGI path prefix, responsive layout and Python-copy controls. Final compile and diff checks pass. Optional engine/deployment combinations remain subject to the documented operational limitations.
