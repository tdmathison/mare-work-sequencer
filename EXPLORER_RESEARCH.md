# Data Explorer research views

Focus, paths and computed edges are temporary operations on authorized data. Focus depth follows recorded entity edges and, only when enabled, computed Shared Indicators edges; category children never count as relationship levels. Exit Focus reloads the original filters against current permissions and restores surviving positions, expansion, selection and viewport. Missing objects are skipped.

Saved Views use schema version 1 in `explorer_views`, migration `explorer-views-v1`. Configuration contains stable IDs, positions, viewport, filters, layout, expansion, focus and shared-edge settings, never case/profile/indicator contents. Each owner is the immutable application user UUID. Maximums are 100 views per owner, 1 MiB per configuration, 2,400 positioned/selected nodes, 400 expanded cases, 120-character names and 1,000-character descriptions. Ownership is enforced for all CRUD operations; owner deletion cascades views.

Complete encrypted application backups include this table through the existing full SQLite snapshot. Complete restore retains source users and UUIDs, so views retain their original owners (not the restoring administrator). Unmapped owners fail the existing installation foreign-key integrity validation and block restore rather than silently assigning views to another user. Selective case/profile imports intentionally do not include personal views. As with other schema changes, older complete archives need upgrading in a compatible application copy before replacement; an old database upgraded by this release gets an empty views table. View schema versions other than 1 are rejected rather than guessed.

Recorded edge evidence is rechecked from current authorized case tag assignments, configured actor/family associations and saved Standard MIP category records. It does not infer provenance, dates, confidence or attribution.

Path search defaults to the filtered graph (and visible focus subset). Explicit all-authorized scope can temporarily add path nodes outside filters. It is limited to 400 filtered or 1,600 all-authorized entity objects, 20,000 recorded edges, 8 relationships, 12 equally shortest paths and 250 ms of traversal/enumeration. Results indicate limits; they do not claim disconnection when traversal was limited. Categories are excluded. Clear Results removes temporary path objects and restores the prior visual classes/displays.

Shared Indicators is off by default. Supported types: MD5 (32 hex), SHA1 (40 hex), SHA256 (64 hex), domains, IP/IP-SRC/IP-DST and HTTP(S) URLs. Type names and hashes normalize casing; domain names use conservative IDNA/DNS validation; IP addresses use canonical validated representations. IP, IP-SRC and IP-DST remain different structured types. URLs normalize scheme, host and default port while preserving exact path, query, escaping and fragment distinctions. Credentials, invalid domains/IPs/hashes, scoped IPv6, whitespace/control characters, filenames and unsupported types do not match. Repeated pairs within a case count once.

Matching reads current structured indicator sections, falling back to legacy structured rows. It does not read arbitrary files as trusted structured indicators and does not create associations or tags. There is no cross-request cache, so edits and permission changes take effect on the next request. An inverted index avoids comparing unrelated case pairs. Limits: 500 ms matching (checked between bounded row/pair batches), 16 MiB per structured carrier, 200,000 rows, 100,000 unique normalized values, 100,000 pair contributions, 2,000 candidate case-pair edges; values present in over 100 cases are omitted. Limited counts are explicitly labeled “At least”; evidence includes at most 200 unique pairs per edge. Minimum match count is 1–100. Matching indicates overlap, never common attribution.
